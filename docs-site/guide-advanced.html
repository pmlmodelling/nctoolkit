Visualization & tips

Interactive and publication-quality plotting, parallel processing with multiprocessing, handy data hacks, and troubleshooting problem datasets.

On this page

Visualization

Call plot() on a dataset for an automatic interactive plot, similar in spirit to the command-line tool ncview — but in Jupyter or a browser. Illustrated below with a sea-surface temperature dataset:

python
ds = nc.open_data("sst.mon.mean.nc")
ds.subset(year=2000)
ds.plot()
ds.plot() — interactive output

The plot type is chosen automatically from the shape of the data. A zonal mean gives a zonal profile:

python
ds = nc.open_data("sst.mon.mean.nc")
ds.subset(year=2000)
ds.tmean()
ds.zonal_mean()
ds.plot()          # zonal profile
ds.plot() — interactive output

A zonal mean tracked over time renders as a Hovmöller-style heatmap — here, the change in zonal-mean temperature relative to an 1850–1869 baseline:

python
ds = nc.open_data("sst.mon.mean.nc")
ds.zonal_mean()
ds.annual_anomaly(baseline=[1850, 1869], window=20)
ds.plot()
ds.plot() — interactive output

Once the data has a single spatial value per time step (e.g. after spatial_mean()), it plots as a time series — here, global mean sea surface temperature since 1850:

python
ds = nc.open_data("sst.mon.mean.nc")
ds.spatial_mean()
ds.plot()          # time series
ds.plot() — interactive output

Publication-quality plots

pub_plot (introduced in v0.9.2) produces a static plot suitable for a paper or presentation, currently restricted to regular lon/lat grids with a limited set of customizations (such as the colour scale):

python
ds.tmean()
ds.pub_plot()

Plotting internals

Interactive plotting is delegated to the companion ncplot package, which inspects the dataset and picks a suitable plot built on hvplot. It favours rapid exploratory analysis over deep customization, but most hvplot customization options — title, logz, clim, and so on — can be passed straight to plot() and are forwarded automatically.

Parallel processing

Two forms of parallelism are available. The simplest is processing files within a multi-file dataset in parallel:

python
nc.options(cores=6)

The second is defining a processing chain and running it over many files yourself with Python's multiprocessing. Before doing this, tell NCToolkit it's about to run in parallel — this switches its internal safe-list of temporary files (used to avoid deleting files still in use) to a process-safe variant:

python
nc.options(parallel=True)

A worked example: convert a folder of files from Celsius to Kelvin, writing each result into a new folder, using 3 worker processes.

python
def process_chain(infile):
    outfile = infile.replace("ensemble", "new")
    if not os.path.exists(os.path.dirname(outfile)):
        os.mkdir(os.path.dirname(outfile))
    ds = nc.open_data(infile)
    ds.assign(tos=lambda x: x.sst + 273.15)
    ds.to_nc(outfile)

ensemble = nc.create_ensemble("ensemble")
import multiprocessing as mp
pool = mp.Pool(3)
for ff in ensemble:
    pool.apply_async(process_chain, [ff])
pool.close()
pool.join()

Once parallel processing is done — especially in an interactive session or notebook — reset the setting:

python
nc.options(parallel=False)

Data hacks

Missing values

python
ds.as_missing(0)                  # set zeroes to missing
ds.as_missing([-1000, 0])         # set a range to missing
ds.missing_as(-9999.99)           # set missing values to a constant
ds.set_fill(-9e38)               # change the netCDF fill value

Shifting time

python
ds.shift(years=-1)   # shift back one year
ds.shift(hours=12)   # shift forward 12 hours

Cell areas, format, dimensions

python
ds.cell_area()              # add grid-cell area (m2)
ds.cell_area(join=False)   # dataset of cell areas only
ds.format("nc4")             # nc1, nc2/nc, nc4, nc4c, nc5
ds.reduce_dims()            # drop length-1 dimensions
ds.drop(month=2, day=29)        # remove leap days
ds.rename({"x": "y"})          # rename a variable

Troubleshooting

Most errors trace back to a quirk in the source data. A few checks and fixes cover the majority of cases.

Check data types

CDO uses the data type stored in the file by default. If a variable is stored as an integer, a comparison like x.temperature > 30 can silently collapse to 0/1 in a way you don't want. See what NCToolkit sees:

python
ds.contents   # shows the data type of every variable

If needed, force floating point before doing arithmetic:

python
ds.set_precision("F64")
ds.assign(temperature=lambda x: x.temperature > 30)

General dataset checks

python
ds.check()   # integer-typed variables, integer time axis, CF-compliance, grid consistency
ds.is_corrupt()   # reads/writes source files to a temp file to catch corruption

Install cfchecker to have check() also verify CF-compliance.

Coordinates stored as variables

If longitude/latitude were written as plain variables instead of coordinates, tell NCToolkit which ones they are:

python
ds.assign_coords(lon_name="lon", lat_name="lat")
